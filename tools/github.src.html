Why do this

The WOODWERD tools keep your work in the browser you use them in. That's simple, but a browser can lose it: clearing your history, a new computer, or Safari tidying up after a week away can wipe it. And what's on the Mac isn't on the iPad.

Connect a GitHub repo of your own once and:

  • Your work is safe. A copy lives on GitHub, not just in one browser.
  • Every device has the same copy. Change something on the Mac and it's on the iPad a moment later.
  • Nothing is ever really lost. GitHub keeps every earlier version, so a mistake can be undone.
  • It's yours. The repo is in your own GitHub account. WOODWERD never sees it, and there's nothing to pay.

It's optional. Every tool works without it. Setting it up takes about 10 minutes, once.

How it fits together

A repo is a folder on GitHub. You make one, and every tool you connect keeps its own file in it. You don't need a repo for each tool.

A token is a long password that lets a tool write to that one folder and nothing else in your account. You make one, and every tool can use it.

After that, each browser you use connects once. From then on, saving to GitHub happens by itself.

Which tools use it

Each tool's own guide says what it keeps in the repo and where its Connect button is.

Connect one tool or several. Each one is separate: connecting or disconnecting one leaves the others as they are.

What you need

  • An email address, for a free GitHub account.
  • A computer, for the setup. Making the repo and token is easier on a big screen.
  • About 10 minutes.
  • Somewhere safe to keep the token, such as your password manager.

1. A GitHub account

Already have one? Sign in and skip to step 2.

  1. Go to github.com/signup.
  2. Enter your email, a password and a username. Your username becomes part of your repo's name, such as your-name/ctrl-data.
  3. Choose the free plan if asked. It's all you need.

2. Your private repo

Already made one for another WOODWERD tool? Use it, and skip to step 4.

  1. Go to github.com/new. You can also click + at the top right of any GitHub page, then New repository.
  2. Owner: leave it as your username.
  3. Repository name: type ctrl-data, or any name you like with letters, numbers and dashes.
  4. Visibility: choose Private. This matters: what the tools keep can say what you own and where it is, and some tools won't connect to a public repo.
  5. Leave everything else as it is. You don't need a README; the tools write one.
  6. Click Create repository.

GitHub now shows a page of setup instructions for programmers. You can ignore all of it. Note the name at the top, such as your-name/ctrl-data. That's what you type into a tool.

3. Your token

GitHub calls this a fine-grained personal access token. It's a long password that only opens the one repo you choose.

  1. Go to github.com/settings/personal-access-tokens/new. You can also get there from your picture at the top right, then Settings, then Developer settings at the bottom of the left side, then Personal access tokens, then Fine-grained tokens, then Generate new token.
  2. Token name: something you'll recognise, such as Ctrl tools.
  3. Expiration: GitHub makes tokens run out. Pick a date about a year away. When it runs out, the tool tells you, and you make a new one the same way.
  4. Resource owner: leave it as your username.
  5. Repository access: choose Only select repositories, then pick ctrl-data from the list.
  6. Permissions: under Repository permissions, find Contents and set it to Read and write. GitHub adds Metadata, read only, by itself. Leave every other permission as No access.
  7. Click Generate token.
  8. Copy the token now. It starts with github_pat_. GitHub shows it once and never again. Paste it into your password manager.
Treat it like a passwordAnyone with this token can change the files in that one repo. Don't email it or post it. If you lose it, or think someone saw it, make a new one and delete the old one on GitHub. What's in your tools is safe either way.

4. Connect a tool

  1. Open the tool and press Connect to GitHub. Its guide says where the button is.
  2. Repo: type your username, a slash and the repo's name, such as your-name/ctrl-data.
  3. Token: paste the token from step 3.
  4. Press Connect.

The tool writes its own file to the repo, and a README that says which tool wrote it. If the repo already holds that tool's file, from another device, the tool asks which to keep before anything changes.

For a second tool, do step 4 again with the same repo and the same token. Some tools offer to reuse a repo another tool already connected in the same browser, so there's nothing to paste.

Phones

Some tools are review only on a phone: you can open and search, but changes are made on a bigger screen. A phone like that only reads from GitHub, so it doesn't need a token that can write.

For those, make a second token the same way as step 3, with Contents set to Read-only, and use it on the phone. If the phone is lost, nothing in your repo can be changed with it. Each tool's guide says whether its phone view is review only.

More devices

Each browser connects on its own, once. On your iPad or another computer, open the tool, press Connect to GitHub, and enter the same repo name and token. Your work arrives.

Your token isn't saved anywhere but the browsers you typed it into, which is why you keep it in your password manager. If you've lost it, make a new one in step 3. The old one keeps working until it runs out, unless you delete it on GitHub.

If something goes wrong

The words differ a little from tool to tool. These are the usual causes.

The token is refusedIt ran out or was deleted. Make a new one in step 3 and enter it in the tool. Nothing in the tool is lost.
Repo not foundCheck the name is your username, a slash, and the repo name, such as your-name/ctrl-data. Check the token was made for that repo.
Can't write, or read onlyThe token is missing write access. On GitHub, edit the token and set Contents to Read and write. On a review-only phone, read only is expected.
The repo is publicOn GitHub, open the repo, then Settings, and at the bottom change its visibility to Private.
OfflineNo internet. Changes wait in the browser and go when you're back.

To stop syncing a tool, press its Disconnect. The token is deleted from that browser for that tool, and your work stays in the browser and on GitHub.

Words used here

GitHubA website for keeping files, with a history of every change. Free for this.
RepoShort for repository: a folder on GitHub. Yours is private, so only you can see it.
TokenA long password that only opens what you chose when you made it. Some tools call it a key.
SyncA tool and GitHub swapping changes, so both have the same copy.
CommitOne saved change on GitHub. Each sync makes one, which is how GitHub keeps the history.

Privacy

A connected tool talks only to GitHub, only for your repo, and only after you connect. The token never goes in a file, a link, an export or the repo.

Every WOODWERD tool runs from woodwerd.github.io, so the tools you open in the same browser can see each other's saved token. That's how one token serves them all, and it's why the token should open only that one private repo, with Contents and nothing else.
